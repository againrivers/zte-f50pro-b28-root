# 05 · B28 专属细节

> 本文档记录 `F50ProV1.0.0B28` 的全部实测参数。
> 其他固件版本**不要**直接套用这些偏移和结构。

---

## 1. 为什么单独写一篇

社区工具包对 B10～B27 提供了预打包镜像，但 B28 没有。而且包里的"多版本"其实是同一份构建：

```
tos.bin (标注 B10)  ─┐
tos.bin (标注 B15)  ─┼─  字节完全相同，来自 2026-06-08 构建
tos.bin (标注 B27)  ─┘
```

与 B28 实机 dump 的 TrustOS 对比：

| 指标 | 数值 |
| --- | --- |
| 总字节 | 5,195,528 |
| 不同字节 | 611,443 |
| 差异比例 | **11.77%** |

**结论：B28 不能刷社区的 TrustOS。也不需要刷。**

## 4. `init_boot_b` 的精确结构

```
偏移            大小            内容
────────────────────────────────────────────────────
0x000000       4096            boot header（magic "ANDROID!"）
0x001000       0               kernel（本设备为空，kernel_size=0）
0x001000       2,263,924       ramdisk（LZ4 legacy 压缩）
0x22A000       2,304           AVB0（vbmeta blob）      ← 页对齐位置
...
0x7FFFC0       64              AVBf（footer）           ← 分区末尾 -64 B
0x800000       —               分区结束（8 MB）
```

实测值：

| 项 | 值 |
| --- | --- |
| 分区大小 | `0x800000`（8 MB） |
| header 大小 | 4096 |
| 项 | 原厂 | 补丁后 |
| --- | --- | --- |
| ramdisk 大小 | 2,630,294 | 2,263,924 |
| cpio 大小 | 4,865,536 | 2,918,912 |
| `AVB0` 位置 | `0x284000` | `0x22A000` |
| `AVBf` 位置 | `0x7FFFC0` | `0x7FFFC0` |
| vbmeta 大小 | 2304 | 2304 |

> footer 三元组 `(vbmeta_offset, vbmeta_offset, vbmeta_size)` 在两版里都自洽：
> 原厂 `(0x284000, 0x284000, 2304)`，补丁后 `(0x22A000, 0x22A000, 2304)`。

原厂镜像 SHA1：`cda1711e475897ea6617c7b6b62a634058390704`
（这个值要写进 `.backup/.magisk`，Magisk 卸载时用它还原）

### header 关键字段（小端）

```
offset 0    : magic         "ANDROID!"
offset 8    : kernel_size   (u32)
offset 12   : ramdisk_size  (u32)     ← 补丁后要更新这个
offset 16   : os_version    (u32)
```

### AVB footer（**大端**，64 字节）

```python
footer = img[-64:]
magic = footer[0:4]                      # b"AVBf"
maj, mi, orig_size, vb_off, vb_size = struct.unpack(">IIQQQ", footer[4:36])
#                      ↑ 大端！用 "<" 会读出天文数字
```

B28 实测：`vb_off = vb_size = 2269184`，与 `AVB0` 位置一致。

## 5. 原厂 ramdisk 的 cpio 结构

LZ4 **legacy** 格式（magic `02 21 4C 18`），不是 frame 格式。

解压后是 newc cpio（magic `070701`），B28 原厂共 **22 个条目**（含 TRAILER，`dev` 重复一次）：

```
dev              dev/null         dev/console      dev/urandom
debug_ramdisk    init             metadata         mnt
proc             second_stage_resources              sys
system           system/bin       system/bin/snapuserd
system/bin/snapuserd_ramdisk      system/etc
system/etc/init  system/etc/init/snapuserd.rc
system/etc/ramdisk                system/etc/ramdisk/build.prop
TRAILER!!!
```

> ⚠️ **原厂镜像里 `dev` 条目重复出现两次**（索引 0 和 5）。
> Magisk 处理时会因此报错，构建时必须去重。

原厂 `init` 是 **3,507,424 字节** 的完整二进制，补丁后被替换成 197,256 字节的 `magiskinit`。

打过补丁后是 **33 个条目**：

```
22（原厂） − 1（去重 dev） + 4（.backup/ + 3 文件） + 8（overlay.d/ 2 目录 + 6 文件） = 33
```


```
init                      ← 替换为 magiskinit (197,256 B)
.backup/.magisk           ← 126 B
.backup/.rmlist           ← 148 B
.backup/init.xz           ← 1,201,992 B
overlay.d/adbip.rc        ← 582 B
overlay.d/sbin/init-ld.xz ← 1,556 B
overlay.d/sbin/magisk.xz  ← 128,872 B
overlay.d/sbin/stub.xz    ← 26,464 B
overlay.d/sbin/start_adbip.sh  ← 1,343 B
overlay.d/sbin/no-aoa.sh  ← 731 B
```

## 6. `.backup/.magisk` 的确切内容

Magisk 靠这个文件判断"原厂状态"，格式必须是：

```
KEEPVERITY=true
KEEPFORCEENCRYPT=true
RECOVERYMODE=false
PREINITDEVICE=metadata
SHA1=cda1711e475897ea6617c7b6b62a634058390704
```

- `PREINITDEVICE=metadata` —— B28 有独立的 `metadata` 分区（64 MB），必须对上
- `SHA1` —— 原厂 `init_boot_b` 的 SHA1，用于"卸载 Magisk"时还原

### `.backup/.rmlist`

NUL 分隔的待删除列表（Magisk 卸载时用）：

```
overlay.d\0overlay.d/adbip.rc\0overlay.d/sbin\0overlay.d/sbin/init-ld.xz\0...
```

## 7. Magisk 与 su

| 项 | 值 |
| --- | --- |
| Magisk 版本 | `1e3edb88(28103)` |
| daemon 版本串 | `1e3edb88:MAGISK:R` |
| **su 路径** | **`/debug_ramdisk/su`** |
| 授权策略 | `/data/adb/magisk.db` → `policies` 表 |

Magisk 28+ 不再提供 `/system/bin/su`，所有脚本都要改路径：

```bash
# 错
adb shell su -c id
# /system/bin/sh: su: inaccessible or not found

# 对
adb shell /debug_ramdisk/su -c id
# uid=0(root)
```

### 无屏幕设备的授权预置

```bash
/debug_ramdisk/su -c "sqlite3 /data/adb/magisk.db \"
  UPDATE settings SET value=3 WHERE key='root_access';
  INSERT OR REPLACE INTO policies (uid,policy,until,logging,notification)
  VALUES (2000,2,0,1,1);
\""
```

`uid 2000` = `shell`，`policy 2` = allow。

## 8. Magisk 运行环境必须补齐

B28 上刷完 root 后，`/data/adb/magisk/` **是空的**，导致：

```
** post-fs-data mode running
* Initializing Magisk environment
* Magisk environment incomplete, abort
```

补齐 11 个文件后才正常（详见 [01-root.md 第 6 节](01-root.md)）：

```
boot_patch.sh  busybox  init-ld  magisk  magisk32  magisk64
magiskboot  magiskinit  magiskpolicy  stub.apk  util_functions.sh
```

判断标准只看一行日志：

```bash
grep "Running post-fs-data.d scripts" /cache/magisk.log
```

## 9. B28 的已知结论

| 问题 | 结论 |
| --- | --- |
| 需要刷 TrustOS 吗 | **不需要**，且不该刷（社区包不匹配） |
| 需要 `dis_avb_ex` 吗 | **不需要**，保持 AVB 结构完整即可 |
| 能降级到 B27 吗 | **不能**，没有完整固件，且 anti-rollback 状态未知 |
| 能改 `/vendor` 吗 | **不能**，erofs 只读（`dm-15`，`veritymode=enforcing`） |
| 有屏幕吗 | **没有**，所有交互必须靠 ADB / UFI-TOOLS |
| 有 USB Host 吗 | **没有**，`musb-hdrc` 只有 device 模式 |
| WiFi 能做中继吗 | **不能**，固件只有 AP 模式（AIC8800，未开放 STA） |

## 10. 一个容易忽略的细节

`spd_dump` 在写 B28 时会打印：

```
Device is using slot b
Start to write partition w_force, type CTRL + C to cancel...
Write Part Done: w_force, target: 0x800000, written: 0x800000
Force Write init_boot_b Done
```

**它把目标分区名报成了 `w_force`**——这是这个版本 `spd_dump` 的显示 bug。

实际写入位置是对的（`init_boot_b`），而且它会自修复分区表。

看到 `w_force` 不用慌，只要最后一行是 `Force Write init_boot_b Done` 就是成功。
